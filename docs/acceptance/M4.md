## 真实 SQLite 桌面检查

- Windows WebView2 发布构建打开临时 SQLite 文件并双击编辑 `sample.name`。Enter 后查看修改集，确认主键为 `1`、旧值为 `first`、新值为 `edited-windows`。用独立 SQLite 连接读取仍为 `first`。点击关闭标签并取消后草稿仍在。关闭窗口出现退出保护，选择「提交并继续」后窗口关闭，独立 SQLite 连接核对 `name=edited-windows`、BLOB 为 `00FF`、生成列为 `14`。再次以只读方式打开数据库，在深浅主题确认只读提示和禁用按钮，切回读写后验证 F2 弹出编辑器并获得焦点。
- Ubuntu WebKitGTK 发布构建在 Xvfb 打开临时 SQLite 文件和两个表标签。切换标签后，已暂存的修改仍显示。暂存一个更新、一个 DEFAULT 新增和一个删除。提交确认列出 `main.sample` 和待删除行数。第二连接先改动待删除行，界面报告第三项冲突并保留三项草稿，独立读取确认更新与插入均已回滚。恢复测试冲突前的值后再次提交，网格报告三类操作各 1 行并刷新行数。独立读取确认行 1 已更新、行 2 已删除、新行 4 使用 DEFAULT、BLOB 及生成列保真。随后暂存一个新增，切换到只读模式时出现保护提示，选择放弃后切换成功。
- 待验项目为 Windows 实际中文 IME 候选词输入、异常断电、远端 CI 和维护者签核。自动化合成事件覆盖组合输入期间 Enter 和 Esc 不触发确认或取消。

## 使用限制

修改集以表为提交单位。包含截断值的行保留只读，单次提交上限为 256 行和 1 MiB。结果无法确认时先刷新并核对实际数据库状态，再决定如何处理草稿。其他边界见 [M4 架构](../architecture/M4-data-editing.md)。
