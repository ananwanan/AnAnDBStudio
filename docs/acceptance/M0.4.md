## Scope

- Replace static explorer/welcome layout with a Dockview workbench.
- Provide Explorer, Welcome and Results panels with dockable tabs and split groups.
- Open, activate and close panels without duplicates.
- Synchronize the header toolbar's active state when the active panel changes.
- Support Ctrl+Tab, Ctrl+Shift+Tab and Ctrl+W while avoiding text-editing targets.
- Persist and restore layouts, recover from malformed saved state and reset to the default layout.
- Respect light/dark/system theme and desktop scaling.

The Results panel is a placeholder; real SQL execution and database operations remain out of scope for M0.4.

## Static inspection and outstanding hardening

- `src/App.tsx` subscribes to Dockview add/remove/active/layout events and refreshes the panel snapshot; `AppHeader.tsx` derives its highlighted button from the active panel.
- `src/lib/dock-layout.ts` serializes a versioned layout to localStorage and falls back to the default layout for invalid data.
- `src/hooks/useWorkbenchShortcuts.test.tsx` contains shortcut tests.
- At the reviewed code revision, dedicated committed regression tests for header/Dockview active-state synchronization and for layout persistence were **not present**. They are recommended follow-up hardening, even though the interactive checklist was reported passed.
- Layout persistence is debounced; retain a regression test for rapid close/restart in subsequent maintenance.
- The M0.3 acceptance document in this branch still has pending entries and should be reconciled separately with its actual CI and manual evidence.
