# M1.5 — SQLite connection lifecycle and error hardening

**Status (2026-11-08):** Code merged into `dev` in [PR #6](https://github.com/ananwanan/AnAnDBStudio/pull/6) on 2026-11-08. Integrated Windows/Ubuntu CI succeeded on [run 42483034461](https://github.com/ananwanan/AnAnDBStudio/actions/runs/42483034461). This is **integration/CI evidence**, not an independent M1.5 interactive GUI acceptance report.

## Delivered behavior

- Maintain process-local SQLite connection handles with stable opaque IDs, a 32-handle limit, and explicit read-only versus read-write modes.
- Reject empty, malformed, unavailable, non-existent, or non-SQLite database paths without creating a new SQLite database.
- Distinguish invalid connection identifiers, missing/closed connections, capacity errors, database close failures, and metadata failures via structured `AppErrorCode` values.
- Move potentially blocking open/list/close/schema work to Tauri blocking tasks; do not access SQLite directly from React.
- Remove registry entries before closing their handles; a close failure may mean the handle is already absent.
- Keep schema traversal bounded and protect its snapshot; preserve typed frontend IPC decoding.
- Guard monotonically increasing IDs with checked atomic updates (follow-up commit [`68b1319`](https://github.com/ananwanan/AnAnDBStudio/commit/68b13193a834fe116fec6c233a9df2b62566d87b)).

## Known limitations and follow-up

- The current connection registry uses a **global mutex**, including bounded schema reads. Long-running SQL must use isolated connection-level workers/jobs (M2), with cancellation and backpressure instead of holding the registry mutex.
- Connection IDs do not survive application restart. GUI state must re-sync from the live Rust registry (implemented in M1.4); never restore stale IDs from browser storage.
- M1.5 is connection-management hardening only: no SQL execution, user data modification, automatic schema migrations, or storage permission expansion.
- Per-machine GUI observations were not included in the PR #6 CI evidence. See [M1.4](M1.4.md) for GUI-level maintainer-reported validation.
