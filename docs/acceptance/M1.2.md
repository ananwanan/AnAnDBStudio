# M1.2 — SQLite connection registry and typed IPC

**Status (2026-11-08):** Integrated via [PR #6](https://github.com/ananwanan/AnAnDBStudio/pull/6); four Windows/Ubuntu jobs passed in [CI 42483034461](https://github.com/ananwanan/AnAnDBStudio/actions/runs/42483034461). No separate M1.2 GUI acceptance is claimed.
**Base:** M1.1 implementation on `feat/m1-sqlite-foundation`.

## Implementation scope

- Keep `anandb-driver-sqlite` independent from Tauri.
- Add a process-local connection registry with stable, opaque string IDs.
- Commands: `open_sqlite_connection`, `list_sqlite_connections`, `close_sqlite_connection`.
- Explicit read-only/read-write selection; existing databases only.
- Return typed connection descriptions (`id`, canonicalized `path`, `readOnly`).
- Use Tauri blocking workers for all connection lifecycle I/O.
- Limit simultaneous handles to 32 and return structured errors.
- Keep permissions restricted to the main window. No filesystem plugin,
  arbitrary file-reading command, SQL execution or schema mutations.
- Update the M0.5 security whitelist when adding approved commands.

The Rust tests cover open/list/close, distinct IDs, invalid/closed IDs,
nonexistent paths, invalid arguments and capacity limits.
The TypeScript tests cover command arguments, response decoding and errors.

## Manual checks (desktop)

M1.2 itself has no GUI. Verify that the Tauri application still starts,
connects to IPC protocol 1 and retains M0 Dockview/theme behaviors.
Connection UI and schema browser belong to M1.4.

## Known limitations

- Connections are process-local and intentionally do not survive app restart.
- The desktop's registry holds SQLite handles under one mutex. Query execution
  and fine-grained per-connection workers are future milestones.
- Paths are supplied by the caller in M1.2; the native file selector and connection dialog were added subsequently in [M1.4](M1.4.md).
- SQL execution, create database, modify schema and connection persistence
  are not included.
