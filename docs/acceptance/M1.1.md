# M1.1 — SQLite driver foundation

**Status (2026-11-08):** Implemented and merged in [PR #6](https://github.com/ananwanan/AnAnDBStudio/pull/6); integrated Windows/Ubuntu checks and Tauri builds passed in [CI 42483034461](https://github.com/ananwanan/AnAnDBStudio/actions/runs/42483034461). Separate local per-OS test logs are not attached.
**Base:** `dev` after M0 PR #5 (`e3b1f3f`).

## Scope

- Introduce a Tauri-independent `anandb-driver-sqlite` crate.
- Open existing on-disk SQLite files in explicitly selected read-only or
  read-write mode. Do not use `SQLITE_OPEN_CREATE` or `SQLITE_OPEN_URI`.
- Reject missing paths, directories, and invalid database contents.
- Verify `PRAGMA user_version` and explicitly close the connection.
- Keep the connection private; worker ownership, Tauri IPC and UI are M1.2+.
- Use `rusqlite 0.41.1` with `bundled` SQLite for consistent builds.
  `rusqlite`/`libsqlite3-sys` are MIT-licensed; SQLite is public domain.

## Acceptance

Run from repository root:

```sh
cargo fmt --all
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

When the new dependency has been resolved, commit the updated `Cargo.lock`.
Then re-run CI-equivalent commands using `--locked`:

```sh
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

The five crate tests cover read-only blocking, read-write persistence,
missing-file rejection, directory rejection, and invalid database rejection.
