## Goal and boundaries

Close the M0 foundation with repeatable evidence that the Tauri desktop starts reliably, maintains Dockview/theme preferences, survives controlled failure and restart, and compiles consistently on Windows and Linux.

No SQLite driver, SQL CRUD, Monaco editor, AG Grid, migration engine, arbitrary shell/filesystem permissions, or unrelated UI redesign in M0.6.

## M0.6.4 — next: exit and failure-recovery checklist (pending)

| ID | Test | Expected result |
| --- | --- | --- |
| 01 | Normal window close, repeat 5 times | No unexpected app crash; each subsequent launch works |
| 02 | Change panel layout and close/reopen immediately | Last completed persisted change restored; note any `350ms` debounce window |
| 03 | Force-terminate **only a test process**, then relaunch | Application boots and restores last persisted state or valid default; no blank screen |
| 04 | Corrupt only the app's `anandb.dockview.layout.v1` storage entry, then relaunch | Invalid layout is removed/fallback works; theme and unrelated storage survive |
| 05 | Test invalid/unsupported layout version and empty panel layout | Safe fallback without crash; reset works |
| 06 | Repeat light/dark/system changes and restart | Explicit preference persists; system preference continues following OS |
| 07 | Exercise `pnpm tauri dev` close path separately from Release executable | Distinguish Tauri CLI lifecycle diagnostics (including earlier `ELIFECYCLE -1`) from actual process crashes; preserve console output if reproduced |
| 08 | Cross-platform exit/relaunch sanity on an actual Linux graphical session | App closes/restarts; preferences remain accessible |

Do not kill unrelated processes. Normal close, forced termination, and frontend unmount are different lifecycle paths. `pagehide` is best-effort; a forced kill does **not** guarantee the most recent unsaved layout change is persisted. Reproduce any issue first, then add the smallest targeted fix and regression test. M0.6.4 is not yet accepted.

## Known risks and non-goals

- CSP is configured for production while `devCsp` is `null`; exercise release WebView explicitly.
- Persistent layout currently uses browser storage; document storage scope, version fallback and reset behavior. Do not silently change the storage backend.
- TypeScript/Rust IPC types remain manually synchronized; M0.6 should verify the supported contract, not introduce a database API.
- Project identity in the roadmap (`cc.ananwanan.anandb`, `anandb`) differs from current `src-tauri/tauri.conf.json` identifier (`com.ananwanan.anandbstudio`) and package/binary name (`anandbstudio`). Decide before stable packaging; do not rename automatically during M0.6 without an explicit release identity decision.
- This is a plan, **not proof of completion**. Add timestamps, CI links, concrete command output and manual evidence only when actually obtained.
