# M0.6 — Startup, persistence, and Windows/Linux acceptance

**Status:** Planned / entry preparation; no M0.6 implementation or acceptance claimed  
**Plan created:** 2026-11-08  
**Prerequisite:** M0.5 [PR #4](https://github.com/ananwanan/AnAnDBStudio/pull/4) must pass final-head CI, be reviewed and integrated into `dev` before creating `feat/m0-startup-acceptance` from updated `dev`. Do not infer authorization to merge from this plan.

## Goal and boundaries

Close the M0 foundation with repeatable evidence that the Tauri desktop starts reliably, maintains Dockview/theme preferences, survives controlled failure and restart, and compiles consistently on Windows and Linux.

No SQLite driver, SQL CRUD, Monaco editor, AG Grid, migration engine, arbitrary shell/filesystem permissions, or unrelated UI redesign in M0.6.

## M0.6.1 first implementation task

The current `.github/workflows/m0-validation.yml` checks TypeScript, Vitest, frontend build, Rust fmt/Clippy/tests and the IPC security script on Windows Server 2022 and Ubuntu 24.04. It does **not** currently compile the complete production Tauri desktop with `pnpm tauri build --no-bundle`, nor prove a real WebView can launch.

First change: extend CI with a dedicated, appropriately timed desktop build smoke job or stage, reusing existing Node/pnpm/Rust setup and Linux WebKit dependencies, **without requiring GUI interaction on the CI runner**. Keep expensive desktop compilation separate enough to identify failures. Verify the actual binary artifact path on each platform rather than assuming a naming convention. Do not add a `--no-bundle` step to a job with insufficient runtime without reviewing its timeout.

Then document manual startup steps on supported Windows and Linux environments. A Linux CI build alone is not equivalent to interactive Linux acceptance.

## Reproduction baseline

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
node --test scripts/m05-security.test.mjs
pnpm build
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
pnpm tauri dev
pnpm tauri build --no-bundle
```

For GUI validation: start the actual Tauri window, verify IPC status and Dockview, change theme and arrangement, close/reopen, corrupt saved layout, restore/reset safely, repeat in production build, then capture OS/runtime versions, exact steps and observed results.

## Known risks and non-goals

- CSP is configured for production while `devCsp` is `null`; exercise release WebView explicitly.
- Persistent layout currently uses browser storage; document storage scope, version fallback and reset behavior. Do not silently change the storage backend.
- TypeScript/Rust IPC types remain manually synchronized; M0.6 should verify the supported contract, not introduce a database API.
- Project identity in the roadmap (`cc.ananwanan.anandb`, `anandb`) differs from current `src-tauri/tauri.conf.json` identifier (`com.ananwanan.anandbstudio`) and package/binary name (`anandbstudio`). Decide before stable packaging; do not rename automatically during M0.6 without an explicit release identity decision.
- This is a plan, **not proof of completion**. Add timestamps, CI links, concrete command output and manual evidence only when actually obtained.
