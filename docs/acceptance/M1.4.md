# M1.4 — SQLite Connection UI and Schema Explorer

**Status:** Implementation patch prepared. Local Windows/Linux validation and CI are **pending**.

**Base:** `dev` at `f25625d6800daf2faffb2bfc9defd5a97a3631b3` (M1.5 merged).

## Scope

1. Native desktop file picker for an existing SQLite file only. Users can also paste an absolute path.
2. Read-only mode by default, explicit read-write opt-in.
3. Centralized in-memory connection state. No stored opaque backend IDs between application restarts.
4. Multiple live connection handles, open/select/close controls, and per-handle schema refresh.
5. Explorer groups: tables, views, indexes, triggers, column metadata, filter, loading, error, empty states.
6. Preserve existing Dockview tabs, keyboard shortcuts, theme, and typed IPC contract. No SQL execution or mutation UI.

## Dependencies

Install the official Tauri v2 Dialog plugin for native path selection (`tauri-plugin-dialog`, `@tauri-apps/plugin-dialog`). Only grant `dialog:allow-open` to the main window, with no arbitrary filesystem permission.

**This patch intentionally does not hand-edit generated lockfiles.** Immediately after applying, regenerate and commit both `pnpm-lock.yaml` and `Cargo.lock` before running frozen/locked CI checks:

```sh
pnpm install --no-frozen-lockfile
cargo check --workspace
```

## Manual desktop acceptance

- Select a real SQLite database in the native file dialog and confirm the default read-only mode.
- Confirm selection cancellation does not open a handle or report an error.
- Open a read-write handle explicitly. Opening an unknown path must not create a file.
- Open two SQLite databases; switch between them; confirm each has independent schema state and refresh.
- Expand table/view fields and inspect primary key positions, types, defaults, hidden/generated columns.
- Filter the tree and refresh. Verify quoted identifiers render as text, never as HTML.
- Close the selected handle; no stale schema remains visible. Restart the app; handles are gone.
- Test corrupt SQLite files, missing files, SCHEMA_TOO_LARGE, and read-only access failures.
- Close/reopen Explorer in Dockview; verify theme and layout restore unchanged.
- Check Windows and Ubuntu GUI behavior and CI results. Record actual evidence before marking accepted.

## Known limitations

- Only the `main` schema is available; TEMP/ATTACH and detailed index/trigger DDL are not in the existing M1.3 contract.
- Connection handles are process-local and intentionally not persisted.
- SQLite schema reads still serialize through the existing connection manager mutex. Per-connection workers and cancellation belong to M2.
- Browser-only Vite preview cannot open real databases; use Tauri desktop.
- No M1.4 test results are claimed in this patch.
