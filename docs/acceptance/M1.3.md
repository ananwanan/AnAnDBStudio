# M1.3 — SQLite schema metadata discovery

**Status (2026-11-08):** Implementation merged via [PR #6](https://github.com/ananwanan/AnAnDBStudio/pull/6). Integrated Windows/Ubuntu CI and Tauri builds passed: [run 42483034461](https://github.com/ananwanan/AnAnDBStudio/actions/runs/42483034461).
**Base:** M1.2 plus the connection IPC test correction.

## Scope

- Discover `main.sqlite_schema` objects: table, view, index, trigger.
- Use `pragma_table_xinfo(?1, ?2)` with bound names for table/view fields.
- Preserve generated and hidden columns, default SQL, declared types,
  `NOT NULL`, and composite primary-key ordinal positions.
- Include implicit autoindex records when SQLite exposes them in
  `sqlite_schema` (other implicit indexes may be absent there).
- Read a consistent snapshot via a DEFERRED transaction, including on
  read-only connections; never execute user SQL or modify the database.
- Cap each reply to 2,048 objects, 2,048 columns per object, 16,384 total
  columns, 65,536 UTF-8 bytes per metadata string, and 4 MiB total metadata text. On overflow return
  `SCHEMA_TOO_LARGE`, without silently returning partial metadata.
- Add typed Tauri command `get_sqlite_schema`, runtime TypeScript decoder,
  error normalization and least-privilege permission.

M1.3 only provides metadata APIs. Explorer tree presentation is M1.4,
SQL IDE is M2, and result browsing is M3.

## Known limitations

- Only the `main` schema is enumerated; TEMP and ATTACH are not supported.
- No index constituent-column/uniqueness information yet. Index objects are
  identified by their SQLite schema records; unnamed implementation-specific
  indexes may not be enumerated.
- The M1.2 global registry mutex remains held during bounded metadata reads.
  M2 will require per-connection workers for long-running work and cancellation.
- Schema text is untrusted metadata, not executable or trusted HTML.
- M1.3 does not change M0's IPC protocol version or create new SQLite files.
