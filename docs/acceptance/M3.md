表分页复用连接线程并逐页释放浏览事务。完整 SQL 结果由原语句逐行写入有上限的临时文件，翻页不会重放 SQL。默认执行仍使用 M2 预览。细节见[架构、IPC 和容量约束](../architecture/M3-data-browser.md)。

主要文件为 `crates/anandb-driver-sqlite/src/browse/`、`query.rs`、`worker.rs`，Tauri 命令和原生保存位于 `src-tauri/src/commands/`，React 数据标签和网格位于 `src/components/data-browser/`，IPC 定义和解码位于 `src/services/`。

## 大数据测试

```sh
cargo test -p anandb-driver-sqlite --locked --test data_browser large_table_page_benchmark -- --nocapture
```

测试创建真实磁盘数据库，写入 10 万或 100 万行，重新打开只读连接。每次取 100 行并校验首尾 ID、结束标记和实际 JSON 大小。时间为同一连接连续 5 次调用的中位数，包含线程调度和编码行值的开销，JSON 序列化大小单独测量。VM 步数来自等价的 SQLite 分页语句，使用 101 行探测尾页。以下为两平台 Debug 构建实测。

| 行数 | OFFSET | 返回行数 | JSON 字节 | Windows 中位耗时 | Ubuntu 中位耗时 | SQLite VM 步数 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 100,000 | 0 | 100 | 7,214 | 0.161 ms | 0.139 ms | 616 |
| 100,000 | 100 | 100 | 7,322 | 0.177 ms | 0.135 ms | 816 |
| 100,000 | 99,900 | 100 | 7,522 | 2.724 ms | 1.575 ms | 200,411 |
| 1,000,000 | 0 | 100 | 7,214 | 0.218 ms | 0.207 ms | 616 |
| 1,000,000 | 100 | 100 | 7,322 | 0.217 ms | 0.162 ms | 816 |
| 1,000,000 | 999,900 | 100 | 7,622 | 28.367 ms | 14.451 ms | 2,000,411 |

相同浅页的传输量和 SQLite 步数与表总行数无关。深 OFFSET 的工作量随跳过行数增长，传输仍只有一页。React 使用实际 Community 网格组件驱动视口跨多个块并回到首块，验证逐块加载及旧块淘汰。排序不匹配索引时，SQLite 可能先扫描或排序大量数据，本测试未测这类查询或整机帧率。

## 桌面验证

- **Windows 发布版人工操作**：打开百万行 SQLite，双击普通表、右键打开 WITHOUT ROWID 表，多个标签并存。跳到第 999,901 行并看到总行数 1,000,000。验证百万行表的 TEXT 降序，首行的 ID 为 1,000,000。确认 Unicode、int64 上下界、BLOB 字节数、NULL 与深浅主题。SQL 编辑器运行两条语句，将含两个同名列的 450 行 JOIN 打开为独立数据标签。关闭连接后看到数据标签失效。剪贴板报告复制成功。通过原生对话框导出 CSV，核对落盘内容为完整的 19 字节 int64 数字。
- **Ubuntu 发布版 GUI（WSL2 + Xvfb）**：连接真实百万行 SQLite，打开普通表和 WITHOUT ROWID 表，调整资源管理器分隔线。指针拖放将两张真实表分成左右两个面板；左侧跳到第 999,901 行，再组合 `big DESC` 和 `big IS NOT NULL`，确认两条边界值记录及右侧原有两行。按 Ctrl+C 复制单格并读取 X11 剪贴板，核对为 `Unicode 猫`。通过 GTK 保存对话框导出 TSV，核对落盘内容为 `other-tab`。
- **待确认**：Windows WebView2 下的鼠标拖放与分屏、Windows IME 回归。Windows 桌面自动操作分别在普通窗口和最大化窗口尝试拖动，没有观察到标签换组。Ubuntu 指针拖放已在发布版验证。

## 已知限制

- 默认表浏览提供实时分页。并发修改和深 OFFSET 的限制见架构文档。对频繁使用的排序/筛选组合可使用匹配索引。
- 完整 SQL 结果须在运行前选择，受原查询超时、每份 64 MiB/100 万行、每连接 4 份结果和闲置期限限制。大型字段有明确标记的预览，完整选区导出仅包含可传输的原值。
- Windows/Linux 验证为本地证据，功能分支 GitHub CI 未运行。Windows 剩余手工项目完成前，M3 未签核为全部验收通过。
