## Architecture and security contract

- Registered Rust commands: `get_app_info`, `check_ipc_protocol` only. The scaffold `greet` was removed in M0.5.5.
- Frontend IPC is centralized under `src/services/ipc-contract.ts`, `ipc.ts` and `app-info.ts`. Responses are decoded from `unknown`; static types alone are **not** considered runtime validation.
- Server errors use stable codes `INVALID_ARGUMENT`, `PROTOCOL_MISMATCH`, `INTERNAL`; client-only codes include `TRANSPORT_ERROR` and `INVALID_RESPONSE`.
- `check_ipc_protocol` accepts a JSON value and validates the numeric range explicitly in Rust. Missing command arguments and malformed requests can still be rejected by the Tauri extraction/transport layer before custom errors are constructed.
- `src-tauri/build.rs` declares the custom-command manifest. `src-tauri/capabilities/default.json` permits only `allow-get-app-info` and `allow-check-ipc-protocol` for the `main` window. TypeScript typing is not an authorization control.
- The production CSP restricts scripts to the app origin; `devCsp` is intentionally unset (`null`), so development mode is not proof that production CSP works.
- `scripts/m05-security.test.mjs` enforces an exact command/capability allowlist, no opener dependency, and key CSP invariants. This is **static configuration coverage**, not a runtime privilege escalation test.
